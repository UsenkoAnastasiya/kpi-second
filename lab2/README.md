# Лабораторна 2 — Вимоги, сценарії та трасування (домен «Бібліотека»)

**Домен:** облік книг, примірників, читачів і видач у міській бібліотеці
(той самий, що в [лабораторній 1](../lab1/README.md)).

## Зв'язок з лабораторною 1

Вимоги й сценарії спираються на ER-модель з `lab1/model/library.mmd`:
сутності Book, Author, BookCopy, Reader, Loan та їхні атрибути
(`status`, `email`, `loaned_at`, `due_at`, `returned_at` тощо) беруться
звідти без змін. Нових сутностей у цій роботі не вводиться.

## Структура

- `spec.md` — актори, головні цілі, критерії прийняття (≤1 стор.)
- `requirements/ears.md` — вимоги в нотації EARS (REQ-01…REQ-10)
- `requirements/user-stories.md` — user stories
- `features/*.feature` — Gherkin-сценарії (S-01…S-09)
- `model/usecases.puml` — use case діаграма (PlantUML)
- `docs/usecases.png` — рендер діаграми
- `docs/traceability.md` — матриця трасування вимога ↔ UC ↔ сценарій
- `docs/audit.md` — аудит: топ-3 розбіжності та виправлення
- `adr/` — ключові рішення (MADR)
- `ai/` — слід промптів і перелік використання ШІ
- `DEFENSE.md` — точка входу для рев'ю

## Актори

Reader, Librarian (узагальнені як User) та зовнішня система
Notification Service.

## Межі роботи

Лише вимоги, сценарії та трасування; без коду реалізації та фізичної
схеми БД.
